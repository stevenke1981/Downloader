# AGENTS.md

Guide for coding agents working in this repository. Human-facing docs: [README.md](README.md). CLI reference: [docs/cli.md](docs/cli.md).

## What this is

Downloader is a Rust workspace (`Cargo.toml`, members `core` and `gui`):

- `core` is the library `dlcore` (package `downloader-core`) plus three binaries: `dlx` (headless downloader), `dlxctl` (remote control and local settings) and `downloader-host` (browser Native Messaging).
- `gui` is the Slint desktop app (package `downloader`).

## Layout

| Path | Contents |
|---|---|
| `core/src/engine.rs`, `core/src/engine/` | Segmented HTTP(S) transfer and its retries |
| `core/src/manager.rs`, `core/src/manager/` | Queue, scheduler, persistence, export/import (`core/src/manager/transfer.rs`), automation |
| `core/src/protocols/` | FTP, Metalink, torrent and media. `core/src/protocols/registry.rs` lists the built-in protocol modules |
| `core/src/modules/` | Add-on modules: manifest, approvals, external process host (`core/src/modules/external.rs`, the only place modules spawn processes) |
| `core/src/remote.rs` | Token-authenticated HTTP control API used by `dlxctl` and the browser |
| `core/src/settings.rs`, `core/src/task.rs`, `core/src/util.rs`, `core/src/verify.rs` | Settings, task model, helpers (conflicts, error classes), integrity checks |
| `core/src/bin/dlx.rs` | `dlx` |
| `core/src/bin/dlxctl.rs`, `core/src/bin/dlxctl/` | `dlxctl` and its submodules (modules and settings helpers) |
| `core/src/bin/shared/cli.rs` | Exit codes, error classes and JSON envelope shared by `dlx` and `dlxctl` (included with `#[path]`) |
| `core/tests/` | Integration tests. `core/tests/server/mod.rs` is the local HTTP fixture; `core/tests/cli.rs` covers the CLIs |
| `gui/src/`, `gui/ui/*.slint` | Rust application code and Slint UI |
| `gui/lang/<lang>/LC_MESSAGES/downloader.po` | Translations, generated by `scripts/gen_po.py` |
| `docs/` | `docs/cli.md` (CLI reference), `docs/modules.md` (modules), `docs/dependencies-and-modules.md` (what may run as a process) |
| `scripts/` | Local checks (`scripts/verify-local.ps1`), installer, translation generator |

## Commands

Run from the repository root.

- Test core: `cargo test --release --locked -p downloader-core`
- Lint core: `cargo clippy --release -p downloader-core --all-targets --locked -- -D warnings`
- Lint as CI does: `cargo clippy --release --workspace --all-targets --locked -- -D warnings`
- Format check for the GUI (CI): `cargo fmt -p downloader --check`
- Format one file you own: `rustfmt --edition 2024 <file>`. Avoid `cargo fmt --all` when other people's files are mid-edit.
- Build release binaries: `cargo build --release --locked`
- Quick CLI check: `target/release/dlx --tools --json`
- Windows local checks (fmt, clippy, build, test, node tests): `scripts/verify-local.ps1`
- Translations after changing UI strings: `python3 scripts/gen_po.py` (use `python` on Windows)

Set `CARGO_TARGET_DIR` if you want the build output outside `target/`; nothing else depends on it.

## Rules

- **800-line limit.** Keep every source file under 800 lines. Split into submodules when a file grows; a binary can have submodules through `#[path = "dlxctl/modules.rs"] mod modules;`.
- **No new crates** without the user's approval. `serde_json`, `sha2`, `hex`, `clap`, `tokio` are already dependencies.
- **Processes: argv only.** Use `Command::new(program).args(...)`, never a shell. Downloads run in-process: do not add an executable dependency for a protocol. `core/tests/external.rs` enforces that protocols and the engine never spawn processes. The allowed exceptions are listed in [docs/dependencies-and-modules.md](docs/dependencies-and-modules.md).
- **Human output is stable.** `dlx` and `dlxctl` default output must not change. New machine output goes behind `--json` and is additive.
- **Stable error prefixes.** Messages starting with `file exists:`, `duplicate:`, `not enough disk space:`, `module <id>:` or containing `verification failed` drive `util::error_code` and so the exit codes. Keep those prefixes when you reword a message.
- **Module approval** happens only through `dlxctl modules approve` or the app's Approve button. Never add approval to a remote route, an import file or a settings form.
- **Tokens and credentials** never go in logs, state files, JSON output or docs. Use `DOWNLOADER_REMOTE_TOKEN`.
- **Git:** commit or push only when the user asks.

## Common changes

- **New CLI flag:** add it to `Args` (or a subcommand) in `core/src/bin/dlx.rs` or `dlxctl.rs`, map it to the `Task` or remote field, add a case to `core/tests/cli.rs` and document it in `docs/cli.md`.
- **New exit class:** extend `util::error_code` (returns a stable class) and `exit_code` in `core/src/bin/shared/cli.rs`, then test it.
- **New remote route:** add it to the match in `route()` in `core/src/remote.rs`, return `{"error", "code"}` on failure, then add a `dlxctl` command and a test.
- **New built-in protocol module:** implement `ProtocolModule` in `core/src/protocols/registry.rs` and add it to `builtin()`. Order matters: `builtin()` keeps the existing precedence.
- **New external module behaviour:** see [docs/modules.md](docs/modules.md). Manifests are JSON in `<state dir>/modules/<id>/module.json`.
- **New UI string:** write `@tr("...")` in `gui/ui/*.slint`, then run `python3 scripts/gen_po.py`. The script fails for a new string that has no translation in its table, so add one there first.
