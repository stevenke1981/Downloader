# 小螢幕候選修正與驗證

此修正接續 v0.4.0，尚未建立另一個 Release；v0.4.0 的 tag 與公開附件保持不變。

## 根因與版面契約

- 舊主視窗偏好大小為 1120×700 邏輯像素，預設位置沒有依目前螢幕工作區修正；1024×768 CI 桌面會截掉視窗右側及底部。
- 表格明寫欄寬、間距及 padding 合計至少 850，加側欄與分隔線共 1047 邏輯像素。這是獨立的 client 內溢出，不能只靠移動視窗解決。
- 新預設 client 為 960×640，保留最小 760×480。Windows 等原生視窗建立後，以實體像素讀取目前螢幕工作區、外框與 client 差值，調整首次開窗位置與必要尺寸。工作區資訊包含工作列占用；不變更桌面解析度。
- 表頭與資料共用一個水平捲動區；側欄、詳細資料與對話框各有垂直捲動。詳細資料最多占主視窗高度的 40%，限速與優先權操作分成兩列。
- 主視窗頂部的精簡視窗、系統匣與退出操作保留在捲動區外。首次定位只執行一次，不持續干預使用者移動視窗。

## 重現與證據

CI 的 `win-screenshot.ps1` 僅在隔離 GitHub runner 執行。它不移動、放大或調整應用程式視窗，不變更解析度；記錄螢幕、工作區、外框、client、DPI 與來源 SHA，保留原始 PNG，並要求真實桌面為 1024×768、整個外框位於工作區內。

- 正常應用程式：全新隔離狀態、繁中、空列表。
- 原生渲染 fixture：同一份 AppWindow、相同 renderer、自製資料，760×480 client，分別顯示選取詳細資料及設定對話框。fixture 沒有 Manager、不讀剪貼簿或下載歷史，不傳送原生滑鼠事件。它證明測試狀態的渲染，不代表完整應用程式互動驗收。
- 無畫面回歸：760×480、960×640、1280×800，檢查重要按鈕的實際幾何範圍與精簡視窗 callback；另測初始外框定位、工作列及負座標螢幕。

每次候選的 CI 終態與實際目視結果請參照 PR。原生滑鼠捲動、焦點及不同 DPI 的人工操作未由上述測試取代。100% DPI 的實際截圖與 150%／200% DPI 必須分別記錄；小於 760×480 邏輯像素的可用工作區不屬於本次最小版面目標。
