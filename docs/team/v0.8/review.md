# Adviser review of 0.8 (Fable 5.2) — findings to fix

Scope: uncommitted diff at d107c81 plus core/src/engine/mirrors.rs, core/tests/mirrors.rs. Line numbers are of the working tree.

1 MED task.rs:101, engine.rs:328 (decision a: CHANGE): `Task.final_url` is serialized, so the post-redirect URL of a module's resolved link (0.7 already) and now of a module mirror or user mirror, query included, is written to downloads.json and the dlx state file. This contradicts docs/modules.md:57-58 and docs/cli.md:71 ("the resolved link, its mirrors ... are not saved"), and core/tests/mirrors.rs:361-364 has to null `final_url` to pass. `final_url` is read only at verify.rs:191, in the same run and always after a probe has set it again, so nothing needs it after a reload. Fix: put `#[serde(skip)]` on `final_url` (the struct is `#[serde(default)]`, old files still load); drop the nulling at mirrors.rs:363 and assert the plain serialized task has no `module.bin`; add the same assertion for `resolved_url` in core/tests/modules.rs.
2 MED engine.rs:202, 288-291, 484 + mirrors.rs:148-152, 166-172: `--on-conflict overwrite` is silently turned into a rename when a mirror finishes the download. The primary's `run_source` picks the name, sets `wanted = Some("f.bin")` and `t.file_name = "f (1).bin"`, then fails in the workers; `wanted` dies with the `Err`. The mirror finds `file_name` set and returns `wanted = None`, so `engine::run` never calls `replace_existing`: the new file stays as `f (1).bin` and the old one is kept. Fix: keep `wanted` across sources, e.g. `run_sources` owns `let mut wanted = None` and passes `&mut wanted` to `run_source`, returning it with the winning source. Add a mirrors.rs test: existing `f.bin`, Overwrite, primary with `fail_after`, mirror completes, `f.bin` holds the new bytes and no `f (1).bin` is left.
3 LOW engine.rs:329: a mirror overwrites `t.header_checksums` with its own, usually empty, list. When the primary's probe advertised a digest and a mirror then finishes its `.part` (mixed bytes, the plan's first risk), verification ends as "no checksum" instead of checking the primary's digest. Fix: for `src.mirror.is_some()` replace `t.header_checksums` only when it is empty.
4 LOW dlx.rs:426-429, 434-441, 444-454: `spawn_hook` spawns a task even without `--modules-dir`, and `wait_hooks` selects on `cancel` without bias. A Ctrl+C that lands after the last URL finished (or a failed last URL) can now exit 130 with `summary.completed` counted, also for runs that use no modules; 0.7 returned the real code. Fix: do not spawn (and do not wait) when `registry` is `None`, return `false` from `wait_hooks` when `hooks` is empty, and add `biased;` with the `all` branch first.

## Decisions asked
- (a) Change: see finding 1. It also closes the same gap for `resolved_url` that 0.7 shipped with.
- (b) Keep. Every `Fail::Local` (conflict, mkdir/open/write, disk space, gap, size mismatch, rename) describes this machine or the file on disk, not the mirror; returning it keeps the `disk` and `exists` exit classes right. The primary's error is still what comes back for every `Fail::Source`.
- (c) Keep untested in CI; check once by hand before the release (`dlx --modules-dir ...` with a `--sleep` hook, Ctrl+C during the wait: exit 130, no hook process left). `stop_hooks` aborts and awaits every unfinished handle and `external::spawn` sets `kill_on_drop(true)` (external.rs:32), so the path is sound by reading. Finding 4 makes `wait_hooks` deterministic enough to unit-test later.
